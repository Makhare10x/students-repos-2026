# Z-index Wizards

## Project Overview
ეს პროექტი წარმოადგენს მუსიკალური პლატფორმის(spotify-ს) ინტერაქტიულ ვებ-აპლიკაციას, რომელიც შექმნილია Collaborative Web Build-ის ფარგლებში. პროექტის მიზანია მომხმარებლისთვის მოსახერხებელი, ვიზუალურად დახვეწილი და ფუნქციური ინტერფეისის შექმნა საყვარელი შემსრულებლებისა და სიმღერების სამართავად.

## Team Contributions

ევა   Navigation, Main Content, Sections, Playlist Cards, Responsive Layout
კახა Tables, Navigation, Cards

## Team Decisions
### Development Approach
პროექტი ავაწყვეთ **Mobile First** მიდგომით, რადგან თავიდანვე გვინდოდა მცირე ეკრანებისთვის სტრუქტურის სწორად ჩამოყალიბება და შემდეგ დესკტოპზე მასშტაბირება.
### Task Management
-	დავალებების მართვისთვის გამოვიყენეთ GitHub-ის პლატფორმა. თითოეული ფუნქციონალი თუ გვერდი (Pins, Artist page, Player და ა.შ.) აღქმული იყო როგორც ცალკე "Task", რომელიც სრულდებოდა შესაბამის Feature Branch-ში.
-	თითოეულ წევრს ჰქონდა თავისი პასუხისმგებლობა და დავალებები, რაც წინასწარ იყო გაწერილი.
-	დავალებების ეფექტური მართვისთვის რეგულარულად ვიყენებდით git pull და git merge ბრძანებებს, რათა მომხდარიყო პროგრესის სინქრონიზაცია და სხვის მიერ შესრულებული სამუშაო ასახულიყო საერთო პროექტში.
-	დავალების დასრულების შემდეგ ხდებოდა ცვლილებების გაერთიანება, რაც გვეხმარებოდა იმაში, რომ პროექტის სხვადასხვა ნაწილები (ნავიგაცია, ქარდები, ფლეიერი) ერთიან სისტემად შეკრულიყო.

### Team Communication
გვქონდა სისტემატიური შეხვედრები დავალებების გასანაწილებლად, ვათანხმებდით პროგრესს და შემდეგ ნაბიჯებს.
### Naming Convention
პროექტზე მუშაობისას კოდის ერთიანობისა და მაღალი კითხვადობის შესანარჩუნებლად კლასების სახელებით მკაფიოდ განვსაზღვრეთ თითოეული ელემენტის როლი და იერარქია სტრუქტურაში. გარდა ამისა, აქცენტი გავაკეთეთ სემანტიკურ და აღწერილობით სახელებზე, რათა კლასები გამოხატავდეს ელემენტის ფუნქციურ დანიშნულებას და არა მის დროებით ვიზუალურ მახასიათებლებს.

### Team Lead
გუნდს ჰყავდა Team lead ქეთევანი, მისი პასუხისმგებლობა იყო დავალებების კოორდინაცია, სტრუქტურული გადაწყვეტილებების შეთანხმება და გუნდის საერთო პროგრესის კონტროლი.

## Workflow
პროექტზე მუშაობისას თითოეული წევრი საკუთარ დავალებაზე დამოუკიდებელ branch-ში მუშაობდა. ცვლილებების სინქრონიზაცია და საერთო პროექტში გაერთიანება ხდებოდა Pull Request-ების საშუალებით, რა დროსაც ხელით ვმართავდით Merge Conflict-ებს კოდის უსაფრთხო ინტეგრაციისთვის.
